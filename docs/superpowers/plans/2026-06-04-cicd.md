# CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add GitHub Actions CI (test + coverage gate + gofmt + go vet + golangci-lint) and automated release/tagging via release-please to the `devicedetector` Go library.

**Architecture:** A `ci.yml` workflow verifies every PR and push to `main` with two parallel jobs (test, lint). A `release-please.yml` workflow reads conventional commits on `main` and maintains a Release PR that, when merged, tags `vX.Y.Z` and creates a GitHub Release. All tooling stays out of `go.mod`; third-party action major versions are pinned.

**Tech Stack:** GitHub Actions (`actions/checkout@v4`, `actions/setup-go@v5`, `golangci/golangci-lint-action@v7`, `googleapis/release-please-action@v4`), golangci-lint v2, Go 1.25 (from `go.mod`). Spec: `docs/superpowers/specs/2026-06-04-cicd-design.md`.

**Note on "tests":** This plan produces CI/CD configuration, not Go code, so each task's verification is running the same checks locally (gofmt/vet/coverage/golangci-lint) and validating YAML/JSON, rather than a failing unit test. The authoritative end-to-end check is the introducing PR's own CI run.

## Task 1: CI workflow — test + lint (gofmt, vet)

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Create `.github/workflows/ci.yml`**

```yaml
name: CI

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version-file: go.mod
      - name: Test with race detector and coverage
        run: go test -race -coverprofile=coverage.out ./...
      - name: Enforce coverage threshold
        run: |
          threshold=90
          total=$(go tool cover -func=coverage.out | awk '/^total:/ {print substr($3, 1, length($3)-1)}')
          echo "total coverage: ${total}%"
          if awk -v t="$total" -v thr="$threshold" 'BEGIN { exit !(t+0 >= thr) }'; then
            echo "coverage ${total}% meets the ${threshold}% threshold"
          else
            echo "::error::coverage ${total}% is below the ${threshold}% threshold"
            exit 1
          fi

  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version-file: go.mod
      - name: gofmt
        run: |
          files=$(gofmt -l .)
          if [ -n "$files" ]; then
            echo "::error::these files are not gofmt-formatted:"
            echo "$files"
            exit 1
          fi
      - name: go vet
        run: go vet ./...
```

- [ ] **Step 2: Validate the workflow YAML parses**

Run: `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml')); print('YAML OK')"`
Expected: `YAML OK` (if PyYAML is unavailable, skip — Step 3 is the real check).

- [ ] **Step 3: Run the same checks locally to confirm they pass on current code**

Run:
```bash
go test -race -coverprofile=coverage.out ./... && \
go tool cover -func=coverage.out | awk '/^total:/ {print "total:", $3}' && \
test -z "$(gofmt -l .)" && echo "gofmt clean" && \
go vet ./... && echo "vet clean"
```
Expected: tests pass, total coverage prints `100.0%` (≥ 90%), `gofmt clean`, `vet clean`.

- [ ] **Step 4: Commit**

```bash
git add .github/workflows/ci.yml
git commit -m "ci: add GitHub Actions CI (test + coverage gate + gofmt + vet)"
```

## Task 2: Add golangci-lint to CI

**Files:**
- Create: `.golangci.yml`
- Modify: `.github/workflows/ci.yml` (add a golangci-lint step to the `lint` job)

- [ ] **Step 1: Create `.golangci.yml`**

```yaml
version: "2"
linters:
  default: standard
formatters:
  enable:
    - gofmt
```

- [ ] **Step 2: Add the golangci-lint step to the `lint` job in `.github/workflows/ci.yml`**

Append this step to the end of the `lint` job's `steps:` list (after `go vet`):

```yaml
      - name: golangci-lint
        uses: golangci/golangci-lint-action@v7
        with:
          version: v2.3.0
```

Version note: `golangci-lint-action@v7` pairs with golangci-lint **v2** (which uses the `version: "2"` config schema above). If `v2.3.0` does not resolve, pin to the latest `v2.x` tag from https://github.com/golangci/golangci-lint/releases — this is the single permitted version adjustment; keep the v2 config schema and the `@v7` action.

- [ ] **Step 3: Install the pinned golangci-lint locally and run it**

Run:
```bash
go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.3.0
"$(go env GOPATH)/bin/golangci-lint" run ./...
```
Expected: no issues reported. If golangci-lint reports findings, **fix them in the Go source** (they are real lint issues) and re-run until clean. If the install fails due to the version, use the latest `v2.x` (see Step 2 note) and retry.

- [ ] **Step 4: Confirm formatting/vet/tests still pass after any lint fixes**

Run: `gofmt -l . && go vet ./... && go test ./... 2>&1 | tail -1`
Expected: `gofmt` prints nothing, vet clean, tests `ok`.

- [ ] **Step 5: Validate the modified workflow YAML parses**

Run: `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml')); print('YAML OK')"`
Expected: `YAML OK` (skip if PyYAML unavailable).

- [ ] **Step 6: Commit**

```bash
git add .golangci.yml .github/workflows/ci.yml $(git diff --name-only -- '*.go')
git commit -m "ci: add golangci-lint (v2) to the lint job"
```

## Task 3: release-please automation

**Files:**
- Create: `.github/workflows/release-please.yml`
- Create: `release-please-config.json`
- Create: `.release-please-manifest.json`

- [ ] **Step 1: Create `.github/workflows/release-please.yml`**

```yaml
name: release-please

on:
  push:
    branches: [main]

permissions:
  contents: write
  pull-requests: write

jobs:
  release-please:
    runs-on: ubuntu-latest
    steps:
      - uses: googleapis/release-please-action@v4
        with:
          config-file: release-please-config.json
          manifest-file: .release-please-manifest.json
```

- [ ] **Step 2: Create `release-please-config.json`**

```json
{
  "$schema": "https://raw.githubusercontent.com/googleapis/release-please/main/schemas/config.json",
  "packages": {
    ".": {
      "release-type": "go",
      "include-component-in-tag": false
    }
  }
}
```

- [ ] **Step 3: Create `.release-please-manifest.json`**

```json

  ".": "0.0.0"
}
```
